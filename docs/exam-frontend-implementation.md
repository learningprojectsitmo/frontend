# Экзамены — frontend

## Сделано

- Добавлена страница экзаменов пространства:
  `/app/exams?workspaceId=<id>&examId=<id>`.
- Добавлена кнопка перехода к экзаменам на странице пространства.
- Подключены API экзаменов:
  - список;
  - создание черновика;
  - публикация;
  - записи проектов;
  - очередь;
  - ETA;
  - старт защиты;
  - вопросы;
  - пауза;
  - продолжение;
  - завершение;
  - техническое откладывание;

  - перезапуск попытки.
- Добавлены frontend-типы экзамена, записи, очереди и попытки.

  - название: 1–200 символов;
  - обязательная дата начала с timezone;
  - тип проекта обязателен для публикации;

  - неотрицательные длительности вопросов и перехода.

- Обработана ошибка публикации `questions_not_ready`.
- Добавлен полноценный редактор вопросов типов проектов:
  - загрузка текущих критериев;
  - создание и удаление критериев;
  - редактирование текста и предмета оценки;
  - редактирование непустых уровней 1–5;
  - frontend-валидация ограничений backend;
  - применение шаблонов `product`, `technical_integration`, `research`;
  - сохранение полного списка через `PUT /project-types/{type_id}/questions`.
- Ошибки назначения проекта переводятся в понятные сообщения:
  - черновик экзамена: «сначала опубликуйте экзамен»;
  - закрытая регистрация;
  - неподходящий тип проекта;
  - повторная запись;
  - обязательный или занятый слот.
- Назначение и самостоятельная запись заблокированы в UI до публикации экзамена.
- При ошибке публикации показывается причина:
  для выбранных типов проекта должны быть заполнены критерии и уровни 1–5

- Под табами каждого проекта добавлены два блока при наличии подходящего

  - таймер до начала экзамена;
  - описание экзамена для студентов и кнопка «Открыть экзамен».
- Очередь и текущая попытка обновляются через HTTP polling.
- Добавлено редактирование настроек экзамена через `PUT /settings` с обязательной
  причиной изменения и проверкой версии.
- Добавлено управление слотами защиты:
  - предложение периода от даты экзамена до `+3 часа`;
  - генерация 15-минутных интервалов;
  - сохранение интервалов одной batch-операцией;
  - список свободных и занятых слотов;
  - выбор свободного слота при записи проекта.
- Страница экзамена перестроена в единый ролевой layout:
  - хлебные крошки «Все пространства → пространство → экзамен»;
  - серый информационный header с пространством, датой и кнопкой подключения;
  - описание экзамена;
  - раскрывающиеся критерии для всех ролей;
  - карточка текущей защиты с проектом и круговым таймером;
  - красное состояние таймера при остатке 30 секунд и меньше;
  - таблица участников и очереди;
  - действия «Оценить» и меню действий для организатора.
- Функциональность разнесена по отдельным страницам:
  - `/app/exams` — список экзаменов и настройка для teacher/admin;
  - `/app/exams/view` — просмотр опубликованного экзамена для manager/member;
  - `/app/exams/conduct` — проведение экзамена и управление очередью для teacher/admin.
- Из карточки проекта открывается страница просмотра экзамена, а не страница
  настройки.
- Учитель и администратор видят управление проведением:
  - начать защиту;
  - перейти к вопросам;
  - приостановить и продолжить таймер;
  - завершить защиту;
  - отложить команду;
  - отметить неявку.
- Менеджер видит опубликованный экзамен, критерии, слоты и может записать
  собственный проект.
- Member видит опубликованный экзамен, критерии и общую очередь участников.
- Добавлены заглушки для функций без backend API.

## Что проверить сквозным сценарием

- Реальный экзамен с отдельными аккаунтами организатора, оценщика и участника защищаемой команды.
- Сохранение, восстановление и повторная отправка листа, закрытие окна, принятие, ручной итог и публикация.
- WebSocket после обрыва сети и скачивание ZIP с двумя CSV.

## Сценарии для ручной проверки

### Admin или teacher — организатор экзамена

1. Открыть пространство → «Экзамены».
2. Создать черновик экзамена, выбрать тип проекта и заполнить дату начала.
3. До публикации открыть «Записанные команды» и проверить, что назначение недоступно
   с подсказкой о публикации.
4. Опубликовать экзамен после настройки вопросов выбранного типа.
5. Выбрать проект и назначить его. Проверить запись в списке.
6. В блоке очереди нажать «Начать», затем проверить переход между фазами,
   паузу, продолжение и завершение.
7. Для очереди проверить «Следующий», «Отложить» и «Неявка».

### Manager — руководитель команды

1. Открыть опубликованный экзамен в период регистрации.
2. Выбрать собственный проект команды и записать его.
3. Проверить появление проекта в очереди и ETA.
4. Проверить, что чужой проект нельзя записать от имени manager.
5. Если экзамен черновик или регистрация закрыта, проверить понятное сообщение
   вместо общего «Не удалось добавить проект».

### Member

1. Открыть опубликованный экзамен.
2. Просмотреть доступную информацию и проектные блоки.
3. Проверить, что назначение чужого проекта недоступно.

### Ошибки публикации

1. Создать экзамен с выбранным типом, у которого нет вопросов.
2. Нажать «Опубликовать».
3. Проверить сообщение `questions_not_ready`.
4. После добавления полного списка вопросов повторить публикацию.

## Вопросы и ответственность

В frontend теперь есть редактор вопросов типов проектов. Организатор может открыть
его в карточке экзамена, применить готовый шаблон или создать критерии вручную,
заполнить уровни 1–5 и сохранить список. После сохранения экзамен можно
опубликовать, если backend-проверка готовности пройдена.

## Диагностика оценивания

База экзамена — `/v1/workspaces/{workspace_id}/exams/{exam_id}`. Запросы используют Bearer-токен.

| Метод и путь | Поля, примеры и права |
| --- | --- |
| `GET /v1/workspaces/{workspace_id}/project-types/{type_id}/questions` | `project_type_id`, `min_score: 1`, `max_score: 5`, `questions[]` с `id`, `position`, `text`, `description` и пятью `levels[]`. Пример уровня — `{"score":5,"description":"Все ключевые решения объяснены"}`. Чтение доступно участнику или автору пространства и глобальному admin. |
| `PUT /v1/workspaces/{workspace_id}/project-types/{type_id}/questions`, `POST .../questions/apply-template` | Изменяют критерии типа проекта по правам управления. Принимают `{"questions":[...]}` или `{"template_code":"product"}`. `GET /v1/assessment/question-templates` отдаёт шаблоны авторизованным пользователям. |
| `POST .../attempts/{attempt_id}/finish` | Организатор (teacher/admin с доступом) передаёт, например, `{"expected_version":4}`. Сервер завершает защиту и возвращает `assessment_window` с `opened_at`, `closes_at`, `settings_version` и `project_type_id`. Срок берётся из `assessment_window_minutes`. |
| `GET .../queue`, `GET .../attempts/current`, `GET .../attempts/{attempt_id}` | Доступны тем, кто видит экзамен. Попытка содержит `exam_id`, `registration_id`, `project_id`, `status`, `phase_deadline`, `server_now` и `assessment_window`. Детальная страница использует WebSocket с резервным REST-опросом каждые пять секунд. |
| `GET .../attempts/{attempt_id}/events` | История для организатора через REST. Примеры событий — `started`, `paused`, `resumed`, `finished`. |

Фронтенд открывает форму по кнопке «Оценить» только после успешного `GET .../assessment`. Допуск, роль, вес, критерии и дедлайн определяет сервер. `PUT .../assessment/draft` сохраняет баллы и комментарии. `POST .../assessment/submit` отправляется с пустым объектом после сохранения всех критериев. Сервер возвращает версию отправленного листа. Исторические окна без снимка аудитории не восстанавливаются по текущему составу проекта.

Сервер открывает оценивание при завершении попытки. Для последней команды доступна отдельная кнопка завершения выступления. Статус экзамена учитывает открытое окно оценивания.

Эффективные teacher/admin с участием в workspace видят реестр `GET .../results`, текущий расчёт, принятый балл, историю редакций и участие. Они могут принять расчёт, ввести ручной итог с причиной и опубликовать последнюю редакцию. Итоги для участников доступны только при наличии отдельного серверного контракта. `GET .../exports/csv` возвращает ZIP с ведомостью и участием оценщиков.

Страница экзамена подключается к `WS .../live`, передаёт токен первым сообщением, применяет полные снимки и восстанавливает соединение после обрыва. Пока действующего снимка нет, работает REST-опрос. Итоги и отправки обновляются по REST, поскольку live-поток этих событий не содержит.

Кнопка подключения отображается только при заполненной `connection_url`.

Записанные команды не всегда назначаются менеджерами:

- самостоятельная запись своего проекта выполняется manager команды;
- организационное назначение проекта выполняется организатором экзамена
  (teacher/admin с правами пространства);
- member не может записывать проект команды.

## Пустые слоты и запуск экзамена

- До планового начала и первой попытки таблица объединяет `GET .../slots` и `GET .../queue`. При наступлении планового времени по серверным часам пустые строки скрываются автоматически. Если первая защита началась раньше, таблица переходит к очереди сразу.
- Уплотняется представление очереди. Время существующих записей сохраняется. Фронтенд показывает серверный прогноз из `eta.items[].eta_at`, который уже учитывает порядок и длительность защит без свободных слотов. Перенос на другое время записи доступен организатору явно.
- Наступление планового времени оставляет экзамен в ожидании ведущего. Кнопка «Начать экзамен» подготавливает первую команду в текущей вкладке. Play запускает первую попытку через `POST .../attempts`. Серверного состояния подготовки до попытки нет. До запуска выбранная по позиции команда готовится, таймер показывает «Ожидаем начала». Пауза означает остановку уже запущенного серверного таймера.

### Перенос в свободный слот

Организатор может переместить ожидающую команду в свободный слот в режиме расписания мышью или стрелками на ручке строки. Свободный слот сохраняется сразу через `registrations/{id}/move`. Если меняется позиция команды, фронтенд следом вызывает `queue/{registration_id}/place` с версией из ответа переноса. Перетаскивание между командами по-прежнему сохраняется кнопкой «Сохранить изменения».

Смена слота и перестановка выполняются отдельными запросами. Если перестановка не удалась, фронтенд пробует вернуть запись в исходный слот. При конфликте версии, повторном занятии исходного слота или неопределённом результате запроса он сообщает об ошибке и перечитывает данные. ETA берётся из обновлённого снимка очереди.


## Проведение и перенос записей

- «Перейти к вопросам» до и в момент достижения нуля открывает подтверждение рядом с кнопкой. При превышении кнопка сразу вызывает `POST .../attempts/{id}/questions`. Таймер показывает серверную фазу и её дедлайн по редакции попытки, шестерёнка открывает подтверждение перед переходом к настройкам.
- «Следующая команда» завершает текущую попытку, открывает окно оценки и запускает отсчёт перехода. После перехода вкладка ведущего обновляет очередь и запускает команду, если она по-прежнему первая. При нулевой длительности перехода защита начинается сразу. Кнопка «Начать выступление» позволяет пропустить оставшееся время перехода. «Предыдущая команда» ставит доступную отложенную защиту первой в очереди и ждёт Play.
- Переход отсчитывается от серверного `finished_at` по длительности `transition_minutes`. Автозапуск выполняет вкладка, на которой ведущий нажал «Следующая команда». Если вкладку закрыли или следующая команда изменилась, ведущий может запустить защиту вручную после перехода. У сервера есть фазы выступления и вопросов. Отдельного серверного состояния перехода нет.
- «Отложить» сохраняет причину и вызывает маршрут очереди для ожидающих или маршрут попытки для выступающих. «Вернуть в очередь» и «Поставить следующей» используют `queue/{registration_id}/place`. Следующую команду выбирает серверная позиция. Для возвращённой команды с существующей попыткой используется `restart`.
- Manager может перенести запись через `self-move`, а организатор — через `move` в другой экзамен того же пространства. Доступность слотов проверяется по API; целевой слот передаётся как `null`, если у экзамена нет слотов. Manager также может записать свою команду без слота со страницы экзамена. Период записи соответствует настройкам сервера. Без отдельных дат запись открывается при публикации и закрывается в момент начала экзамена.
- Блок «Прогноз окончания» использует остаток текущего слота из API и прогноз начала последней команды с её длительностью. Отложенные без места исключаются из прогноза. Нижняя граница и устаревший снимок отмечаются в интерфейсе. Счётчик команд не включает записи, перенесённые в другой экзамен или отменённые.


## Аудит доступа и очереди

| Условие | Доступ по текущему API |
| --- | --- |
| Глобальный admin | Чтение и управление экзаменами всех пространств. Каталог организатора включает закрытые пространства. |
| Глобальный teacher | Чтение и управление в пространстве, где он участник или автор. |
| Локальный teacher/admin | Чтение и управление в своём пространстве. |
| Локальный manager | Просмотр опубликованных экзаменов. Самостоятельно меняет только запись своего проекта в период записи и до начала его защиты. |
| Member | Просмотр опубликованных экзаменов в своём пространстве. Запись и организационные действия недоступны. |
| Автор пространства без роли организатора | Просмотр опубликованных экзаменов. Авторство само по себе не даёт права организовать экзамен или записать команду. |

Организационные права и право самостоятельной записи определяются отдельно. Например, глобальный teacher с локальной ролью manager управляет экзаменом и может самостоятельно записать свой проект. Маршрут проведения проверяет организационные права. Действия с регистрацией скрыты после старта защиты, включая отложенную попытку. Организатор может назначить команду на странице экзамена с выбором слота или без слота, если расписание отсутствует. При перестановке учитываются серверные позиции возвращённых команд и проверяется ревизия очереди. Если параллельное изменение прерывает серию запросов, уже принятые перестановки видны после обновления.

Форма оценивания доступна согласно серверному снимку аудитории. Фронтенд больше не использует текущий состав проекта для определения допуска. Ответственный преподаватель команды не назначается отдельной связью. Для итоговых действий применяется эффективная роль teacher/admin пространства по текущему серверному контракту.

## Сверка контрактов для изменений формы, очереди и выгрузки

| Сценарий | Контракт и поведение интерфейса |
| --- | --- |
| Настройки и период записи | Схема Exam допускает прошедшее `starts_at`. Границы записи должны быть не позже начала, а открытие должно быть раньше закрытия. После публикации сервер фиксирует дату, период и типы. В форме используются общий календарь и поле времени, обе границы можно очистить. Прошедшая дата сама по себе оставляет опубликованный экзамен без начавшихся защит в ожидании. Сервер запрещает сохранять новые слоты после наступления начала, поэтому форма проверяет этот случай перед отправкой. |
| Права и запись | Организатор с правами teacher/admin может назначать и переносить после закрытия записи, пока защита команды не началась. Менеджер меняет запись собственного проекта только в пределах серверного окна обоих экзаменов. Доступ member и магистрантов следует их роли в пространстве. |
| Назначение | Обе точки назначения используют один селект с поиском. Модалка проверяет все страницы проектов пространства и типы незаписанных проектов по карточкам. Если все подходящие команды уже в очереди, модалка предлагает перейти к управлению выступлениями. Допустима одна активная запись проекта во всех экзаменах. Список проектов не содержит глобального признака такой записи. Модалка сверяет очереди опубликованных экзаменов пространства и скрывает команды с активной записью. При назначении сервер повторно проверяет уникальность записи. |
| Перенос | Предвыбран исходный экзамен. Можно выбрать свободный слот в нём или другой опубликованный экзамен того же пространства с подходящим типом. Действия используют `move` или `self-move` с причиной и версией записи. Текущий слот исключён из выбора, поскольку запрос на него оставил бы запись прежней. |
| Старт, фазы, завершение | `attempts` и команды попытки управляют отдельной защитой. Дедлайн и пауза приходят с сервера, длительности фаз фиксируются редакцией настроек старта. Истечение времени требует явного действия ведущего. Завершение попытки открывает окно оценки по актуальной редакции настроек. |
| Листы и итоги | Форма, версионируемые черновики и отправка используют `assessment`, `assessment/draft` и `assessment/submit`. Сервер фиксирует аудиторию на момент открытия окна. Принятие и ручной итог после закрытия окна создают редакции, отдельная команда публикует последнюю редакцию. |
| Выгрузка | У Exam есть только серверные состояния `draft` и `published`. Отдельной команды завершения экзамена и проверки завершения в CSV API нет. В интерфейсе архив доступен после завершения последней защиты и закрытия окон оценки, когда очередь больше не содержит ожидающих и отложенных команд. При раннем нажатии показывается «Сначала завершите экзамен». Запрет действует в интерфейсе. |
| Неявка и отложенность | `queue/{registration_id}/place` без позиции возвращает команду в конец, с позицией 1 ставит первой среди ожидающих. Операция меняет позиции, версию регистрации и ревизию очереди. Таблица берёт прогноз начала из нового снимка ETA. Забронированные слоты сохраняются, поскольку очередь и расписание имеют разные контракты. Во время защиты обновляется только прогноз ожидающих команд, активная попытка и завершённые строки сохраняют своё фактическое время. |
| Период защиты | Для организатора и менеджера начало и конец видны в шапке. При наличии расписания окончание берётся из последнего слота, без слотов показывается прогноз при наличии данных. После завершения отображается фактический период защит. |
| WebSocket | Live передаёт полные снимки очереди с ETA и состоянием попытки. Переподключение возвращает полный снимок, HTTP остаётся резервным чтением и используется после команды управления. |


## Оценивание, утверждение и ведомость

- Сервер создаёт окно и фиксирует аудиторию при `POST .../attempts/{id}/finish`. До завершения защиты форма оценки недоступна. Для последней команды интерфейс завершает её выступление и открывает окно через тот же маршрут. Отдельного серверного завершения всего экзамена нет.
- Посетители страницы экзамена получают уведомление справа внизу, если форма подтверждает допуск и оценка ещё не отправлена. Оно появляется независимо от фильтра таблицы. Модалка открывается по «Оценить». Обратный отсчёт рассчитывается от серверного `closes_at`, последние 30 секунд выделены красным. После закрытия модалка показывает причину и время вместо критериев.
- Лист сохраняется автоматически. Фоновые запросы оставляют комментарии доступными для редактирования. После ошибки можно повторить сохранение. Исправление отправленной оценки до дедлайна создаёт редакцию того же листа, и в расчёт попадает только последняя отправленная редакция. Повтор неизменённого листа на сервере идемпотентен.
- Teacher/admin пространства утверждает и публикует итог. До утверждения в таблице ведущего отображается индикатор с подсказкой. «Ведомость экзамена» на детальной странице показывает завершённые защиты, расчёт и веса по группам, утверждённый итог, статус, действия и экспорт CSV. Разбивка запрашивается для строк текущей страницы ведомости через существующий маршрут итога. CSV по-прежнему доступен в интерфейсе после завершения экзамена.
- Все маршруты чтения итога и его редакций, включая опубликованные, требуют эффективной роли teacher/admin и участия в пространстве. Студенческого маршрута в текущем API нет. На странице проекта карточка опубликованной оценки доступна только участнику команды с серверным доступом к итогу. Если у итога появилась новая неопубликованная редакция, карточка продолжает показывать последнюю опубликованную.
