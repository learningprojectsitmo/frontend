# Аудит модуля «Экзамены» · 20 ноября 2026

Изменения внесены во фронтенд. API сверялся с маршрутами, схемами и сервисами из соседнего репозитория `backend`. Сборка, автоматические тесты и выборочные проверки в Chrome подтверждают перечисленные сценарии. Нагрузочный тест на 300 клиентов прошёл в двух локальных процессах сервера с отдельной тестовой базой. Полная браузерная приёмка остаётся открытой.

Таймаут мутации может означать, что сервер успел сохранить операцию. Перед повтором нужно сверить состояние. Особенно это важно для первого создания экзамена, поскольку существующий API не предоставляет клиентский ключ идемпотентности. Введённые данные остаются в открытой форме после отказа. `questions_not_ready` возвращает к разделу вопросов. `registration_not_active`, `project_type_not_allowed` и `defense_already_started` имеют отдельные пользовательские сообщения. При конфликте слота, позиции или версии записи клиент перечитывает доступные данные. Автовосстановление из локального хранилища противоречит существующему тесту формы, который требует начинать новое посещение с пустых полей.

### Тёмная тема

В новых состояниях используются `app-text`, `app-muted`, `app-surface` и общие кнопки. Проверены по исходникам палитры статусов, текущая строка, прошедшие и пустые слоты, панели таймера, оценивание, шкала, портальные подсказки и модалки. На поверхности `#111A2E` контраст `#155DFC` составляет 3,31:1, токена `app-blue` в тёмной теме — 4,71:1, а `blue-300` — 9,62:1. В затронутых ссылках и кнопке «Оценить» используется светлый синий в тёмной теме. Фон текущей строки использует `#155DFC12` в светлой теме и полупрозрачный синий в тёмной. Измерения по токенам не охватывают композицию всех полупрозрачных фонов и фактический рендер браузера.

## Матрица прав

`О` — организатор. Это глобальный admin, глобальный teacher с доступом к пространству через членство или авторство, либо участник с локальной ролью teacher/admin. Владение самим экзаменом служит фильтром вкладки «Мои» и не требуется для управления.

`И` — участник пространства с эффективной ролью teacher/admin. Локальная роль имеет приоритет, глобальная применяется при отсутствии локальной. Глобальный admin без членства может быть организатором, но права на ведомость, утверждение и CSV у него отсутствуют.

`А` — лицо есть в зафиксированной аудитории окна и допущено к оцениванию. Участники защищающейся команды исключаются по снимку аудитории. Доступ на отправку действует до серверного `closes_at`.

Магистрант — категория интерфейса. Действия с записью требуют эффективной роли `manager`, членства в пространстве и авторства проекта. Упоминание магистранта само по себе права не добавляет.

### Расхождения и границы

- Прямые GET-запросы результата и редакций проверяют доступ к экзамену. `ExamResultService.get` возвращает последний итог и предварительный расчёт, а `editions` возвращает редакции без фильтра по публикации. Это серверное расхождение с требованием видимости. На странице проекта действующая проверка фронтенда допускает к запросу только участника команды с правом И и показывает опубликованную редакцию. У обычной команды просмотр опубликованной оценки через этот блок остаётся недоступен. В отчёте и фронтенде это не выдано за серверное ограничение доступа.
- Экзамен имеет сохранённые статусы `draft` и `published`. «Ожидаем начала», «Идёт», «Завершён» и варианты актуальности вычисляются из расписания, попыток и окон. Кнопка «Начать экзамен» подготавливает локальный экран. Фактическое начало — создание первой попытки, а действие «Завершить экзамен» объясняет условия окончания. Отдельных записей о начале/завершении экзамена и маршрута удаления экзамена нет.
- Сервер упорядочивает записи по позициям и освобождает позицию при неявке, отмене и откладывании. Пустые слоты скрываются из живого представления по плановому времени или после начала выступлений. Сохранённые слоты при этом остаются в расписании. Перенос команды в пустой слот — версия записи плюс отдельное изменение позиции при необходимости. Атомарного массового переноса, удаления сохранённого слота и задания для перепланирования по времени в текущем контракте нет. Можно удалить созданный локально слот до сохранения или вручную перенести запись. Компонент предпросмотра массового переноса в текущих маршрутах не подключён.
- После публикации неизменяемы дата начала, период записи и типы проектов. Критерии блокируются после открытия окна для соответствующего типа. Сервер определяет момент закрытия и принимает решение об итогах после закрытия. История настроек и история итога имеют разные маршруты и правила чтения.
- Изменение порядка и слотов выполняется последовательностью отдельных REST-мутаций. Фронтенд перечитывает версии и сообщает о частичном выполнении при конфликте. Атомарного отката всей последовательности сервер не предоставляет.
- Основная детализация использует live-канал и REST-подстраховку каждые 5 секунд при разрыве. Каталог и страница проекта используют REST с собственными интервалами. Снимок очереди содержит абсолютные времена, таймер вычисляется локально и очищает интервал при размонтировании. Дополнительные запросы списков проектов, итогов и окон всё ещё могут быть заметны на большом наборе данных. Виртуализация в рамках этих изменений не внедрялась.

## Используемый API

Пути перечислены относительно `/v1`. Обозначения: `W = /workspaces/{workspace_id}`, `E = W/exams/{exam_id}`, `A = E/attempts/{attempt_id}`, `R = E/registrations/{registration_id}`.

Клиент читает экзамены, слоты, регистрации, настройки и реестр итогов страницами до 100 записей через `limit`, `offset` и `has_more`. Запросы пространств и участников используют свою нумерацию страниц. Маршруты одиночного чтения и событий попытки, истории регистрации и `queue/next` есть на сервере и не нужны основным сценариям текущего интерфейса. Обёртка чтения `attempts/current` существует, активная карточка берёт текущую попытку из очереди.
